# Phase 4 validation

Version 0.19.0 adds eight purpose-based composition contracts, registry 1.0.0 with five measured review candidates, and eight bounded refinement intents with optional controls. New runtime code is original and offline; the browser retains its host/runtime and network boundaries.

## Automated evidence

- 69 Node tests and 45 Python tests cover the existing stack plus catalog ranking, malformed controls, dial extremes, explicit constraint preservation, critique refusal in the token writer, canonical resume, candidate evidence/exceptions and CLI behavior.
- Default schema-2 and explicit schema-1 outputs were compared directly with published 0.18.0 on Node 22 and 24: same-runtime output is byte-identical for all three baseline inputs. Cross-runtime hashes normalize only numeric metadata to 12 significant digits because V8 color diagnostics differ by up to 1.14e-13; exported strings remain exact. Original Node 24 digests are retained as evidence. Numeric monotonicity is tested for the values actually mapped by each dial; no aesthetic quality monotonicity is claimed.
- Six independently authored rendered fixtures are separate from the bundled template library. The deliberately repetitive page triggers all five rules. The decorated form triggers multiple candidates. The editorial page has no candidates; catalog and workspace repetition remains visible with context exceptions. A sensible application form triggers a false-positive rhythm candidate, retained after review. Thresholds were not tuned to conceal that result. See the machine-readable assessment in reports/composition-0.19.0.json.
- Two reserved task briefs exercise layout recommendation for application/operations content. These are deterministic routing fixtures, not a live AI-host benchmark or proof of creative quality.
- Rendered quieter/bolder comparisons preserve identical text, the required input and primary action at 320/1440px. They measure body size, target height, hierarchy and zero-duration reduced motion. Existing browser tests retain hostile-evidence, navigation and accessibility checks.
- The public composition guide renders at narrow/wide sizes with eight contracts and working disclosure controls. Screenshots are actual fixture captures, not generated mockups.

## Behavioral evaluation and limits

An isolated agent used the skill to quiet/distill the decorated application. It preserved exact main text, all four required labeled inputs, the deadline, access guidance and submit action; checked 390/1440px renders, keyboard order, focus and native required validation; and never submitted a completed form. The run exposed unnecessary helper-first wording and a test-specific reference in the installed guide. Both were removed. This first run is explicitly not a blind held-out evaluation because that reference was visible.

A second fresh isolated agent used the corrected instructions to make the menu bolder, then critique it without subsequent edits. It preserved exact six-dish, price, dietary-note and Add-control inventory; retained HTML/CSS; inspected 390/1440px and 200% text scaling; verified 48px controls and keyboard focus; and made no network requests or orders. Its report identified ambiguity between the resolver report schema and studio design-record schema, plus the scoped/substantial boundary. Both distinctions were clarified in the guide. The reviewer also noted that bolder remains a designer procedure when a project has no token system; the documentation now explicitly distinguishes procedures from automatic token effects. These are scoped local agent runs, not proof of implicit host discovery, broad model performance, complete accessibility or backend behavior. The eight new positive/negative trigger prompts remain unmeasured on live hosts. Prior Claude upload and Grok Bot limits remain unchanged.

Composition reports deliberately separate review candidates from accessibility failures. A low candidate count is not success by itself. DOM bounds, inferred surfaces, nested sections, pseudo-elements and missing task context limit coverage. Numeric tokens do not guarantee target size or reduced motion unless components consume them and the result is inspected. Colorize/typeset/polish/harden/distill provide bounded procedures for the agent; they are not automatic DOM rewrite engines.

## Release boundary

All full helper packages receive the same code and references; the portable prompt receives guidance only. Archive verification executes the extracted layout/refinement commands and token controls. Font notices and bytes remain unchanged. The Windows x64 kit restores pinned sources and build inputs without installation scripts; Node/Python and optional browser/Office runtimes remain prerequisites. Publication follows the existing Windows/Linux × Node 20/22, browser and reproducible-hash gates.
