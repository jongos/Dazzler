Fonts with a purpose

Dazzler filters for characters, weights, italics, technical features, and file size before comparing personality. It chooses in context; a ranking score is only a starting point.

Its font catalog covers 25 families, with licensed files for 24 bundled. Web fonts can usually be copied into the project without installing them on your computer.

Colors with a job

A brand seed or curated inspiration becomes a set of semantic roles: text, surface, action, focus, and status. Perceptual ramps help keep those roles consistent.

The helper measures defined contrast pairs. Color harmony alone doesn’t establish readability, and a palette report isn’t a complete accessibility audit.

What if a font needs approval or installation?

The skill should identify the exact source, license, missing requirement, and next step. It should preserve language and style requirements rather than silently substitute an unsuitable face. If an appropriate bundled font is available, selection and project-local copying happen automatically.

05 / BEFORE DELIVERYEVIDENCE OVER ASSUMPTIONS

Good-looking is the beginning.

The review connects the finished interface to its purpose and distinguishes what was checked from what remains unverified.

Fit

Does the hierarchy support the main task? Are the visual choices specific to the audience and content?

Layout

Inspect wide and narrow viewports for overflow, clipping, asset failures, and awkward spacing.

Behavior

Exercise the main action and applicable loading, empty, error, and success states.

Access

Check semantic controls, keyboard use, visible focus, relevant contrast, and reduced motion.

Honesty

Report unavailable checks. A mockup is not a working backend; a screenshot is not a functional test.

“De-slop” means design with intent.

It means improving purpose, hierarchy, grouping, and behavior—not banning a particular font, hue, or layout. The design framework supports that review.

Ten connected capabilities build on Dazzler’s type, color and design framework. Ask for the outcome. The skill selects the useful tools in the background.

01 / Brand importer

Start with what makes you recognizable.

Reads CSS declarations and rendered styles, records sources, and surfaces conflicts. Dazzler resolves the evidence against your existing brand rules before choosing locks.

02 / Design-token generator

One system, carried everywhere.

Generates coordinated type, spacing, radius, elevation, motion and measured colors. Exports CSS, supported DTCG primitives and Tailwind adapters.

03 / Rendered inspector

Look at what actually shipped.

Creates screenshots and findings for overflow, clipping, image failures, labels, text-contrast candidates and focus probes. Findings are reviewed before fixes.

04 / Content stress tests

Design for the awkward cases.

Temporarily tests long labels, large numbers, missing images, empty data and visible errors. These DOM simulations do not change your source or prove server recovery.

05 / Font pairing lab

Compare the voice and the fit.

Renders actual copy with licensed font pairs, measures fallback/final wrapping, file size and local load time. These measurements support judgment rather than replace it.

06 / Chart styling

Make the data distinguishable.

Creates categorical, sequential and diverging palettes with labels, pattern references and marker/dash cues. Graphic contrast is measured against the selected background.

07 / Icon & illustration catalog

A coherent visual vocabulary.

Adds 12 original outline icons and three geometric illustrations. Each has usage guidance, technical metadata, a file hash and its license.

08 / Reversible change previews

See the difference. Keep an undo path.

Shows before/after screenshots and source differences. Single-file apply/revert uses checksums and refuses to overwrite edits made since the preview.

09 / Document & slide editions

Carry the brand beyond the screen.

Exports printable HTML briefs and slide editions from the same system. Optional host libraries support DOCX/PPTX. HTML can embed verified font exports; native formats reference fonts.

10 / Cross-platform evaluation

Test the work, not just the package.

Provides four repeatable briefs and a configurable real-host runner. Reports record artifact assertions and hashes; missing host runs and manual reviews remain clearly untested.

What runs where?

Brand-file import, assets, change plans and HTML export use Python’s standard library. Tokens and charts use Node with Dazzler’s bundled color engine. Browser inspection, font comparisons and screenshots need an available Playwright/Chromium runtime or host browser. Native DOCX/PPTX export needs available Python document libraries.

Dazzler chooses an available path and reports what could not run. It does not install tools into your project just because a helper exists. A layout audit is not full accessibility certification; local font timing is not network performance; an exported slide deck still needs visual review.

Platform downloads and developer reference

Optional editions support Claude/Fable, Gemini CLI, Cursor and GitHub Copilot. Full packages contain the same studio scripts, asset catalog and evaluation briefs; capabilities still depend on the host.

07 / DESK REFERENCEKEEP THIS PART HANDY

Your next good brief.

Use $dazzler-frontend to [make or improve something] for [an audience]. Help them [do the main thing]. Keep [important constraints].

You can leave the visual decisions open. More detail is useful when it describes the job, not when it creates work for you.

For developers: what powers the workflow?

The local font helper checks bundled files and exports project-local assets with their licenses. The bundled color helper generates tokens, contrast reports, and previews. Normal use requires no npm install or third-party Python packages. The agent uses available Python and Node runtimes internally; when a runtime is unavailable, it should continue using verified assets and disclose checks it couldn’t run.

Implementation should reuse your framework, package manager, components, and tokens. The skill adds design guidance; it doesn’t require a new stack, Claude CLI, or an Anthropic API key.

For teams: records, sources, and limits

Substantial projects may benefit from a durable design record. Small edits don’t require one. Preserve authentic project content; don’t invent testimonials, metrics, logos, or company claims.

The font catalog is a snapshot dated September 28, 2026. Bundled font licenses remain separate from the plugin’s Apache-2.0 license. See the closing notes for current files and attribution.

Dazzler renders standard charts, custom networks, treemaps and geographic outlines. Review the chart beside its source table; download its SVG and CSV.

React + Office

Microcharts supplies compact React trend components and previews. The optional mschart adapter produces editable Word and PowerPoint charts when R and its packages are available.

Use $dazzler-frontend to turn these quarterly results into a clear chart and a compact trend for our dashboard. Preserve the source values and our brand.

What is included, and what needs a runtime?

Browser previews and SVG generation use bundled offline libraries. React source integrates with the existing project. Native Office export needs R, mschart and officer; it was not run on the maintenance host. Missing dependencies produce a clear fallback report, never a claim that a static image is an editable chart.

Automatic adapters cover seven standard chart types, three custom layouts and compact React trends. They do not expose every upstream feature. The source table, report and rendered review remain part of delivery.

11 / Local by design

Ready without a round trip.

Bundled fonts, palettes, templates and rendering engines run locally. Dazzler checks its installed resources, selects the smallest compatible tool and keeps your existing framework.

Lightweight interactions

Standalone image guides use a 3.8 KB browser-native runtime. Existing React and Vue projects keep their matching adapters.

Smaller chart previews

The chart compiler stays in the exporter. Browser previews receive the compiled specification and a runtime that is 34% smaller than the previous release.

Controlled maintenance

A release-only Windows x64 source kit supports offline rebuilds on that platform. Updates are reviewed imports, never automatic upstream substitutions.

Node and Python remain host prerequisites. Browser inspection and editable Office output require their optional local tools. Integrity checks and input limits improve reliability; they do not certify every future design.
